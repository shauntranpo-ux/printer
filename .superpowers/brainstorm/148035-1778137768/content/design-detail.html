Per-asset BV3 tables, sidecar YAML pattern (same as Strategy C fitter). Two scripts, no source patching.

Part A — scripts/tune_s1_gates.py
~50 lines · no dependencies · runs in <1s
Reads backtesting/output/ev_sweep_all.csv, picks the Sharpe-optimal min_ev_base_s1 per asset, writes per-asset overrides into config.json. For BTC (all backtests negative), picks the least-bad Sharpe value and logs a warning.
Input → ev_sweep_all.csv
Output → config.json: "min_ev_base_s1_btc": 7, "min_ev_base_s1_eth": 25, "min_ev_base_s1_sol": 16, "min_ev_base_s1_xrp": 17
Part B — backtesting/training/bv3_calibrator.py
follows Strategy C sidecar pattern
For each asset, joins settlements with 1m price bars. Simulates entries at each of the 13 time-to-expiry marks (1–13 min) within every 15m market window. Computes empirical continuation win rate per (distance_bucket × time_bucket) cell.
Entry simulation
For each settlement × each T ∈ [1..13 min]:
 entry_time = close_time − T min
 spot = 1m bar close at entry_time
 dist = |spot − strike| / spot
 win = (spot>strike ∧ result=1) ∨ (spot<strike ∧ result=0)

bot_strategy.py — small runtime change
Add a _load_bv3_table(asset) helper called once at startup. It reads the sidecar YAML and caches it in a module-level dict. The existing _s1_empirical_win_prob() function looks up the cached table first, falls back to the embedded _BV3_TABLE if no sidecar found. No structural change to the signal logic — just a data swap.
