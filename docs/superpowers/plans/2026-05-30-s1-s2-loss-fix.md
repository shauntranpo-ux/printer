## Diagnosis Summary

### Root Cause 1: S1 Calibration-Production Parameter Mismatch (CRITICAL)

The win rate table `_S1_WIN_RATE` in `bot_strategy.py` was produced by `scripts/calibrate_winrates.py`.
The calibration script runs S1 simulation with DIFFERENT `ema_long` and `min_dist` than the live bot:

| Asset | Calibration `ema_long` | Live `ema_long` | Calibration `min_dist` | Live `min_dist` |
|-------|----------------------|-----------------|----------------------|-----------------|
| BTC   | 10                   | 12              | 0.0025               | 0.002           |
| ETH   | 10                   | 7               | 0.0030               | 0.002           |
| SOL   | 8                    | 12              | 0.0050               | 0.002           |
| XRP   | 10                   | 12              | 0.0040               | 0.002           |
| DOGE  | 8                    | 12              | 0.0080               | 0.001           |

**Effect:** Live bot trades weaker EMA signals (shorter `ema_long`) and closer to strike (lower `min_dist`) than what calibration measured. Actual win rates are ~5-15% lower than table. At entry ≈75c, breakeven WR is 75%. Table says 97%, real is ~70% → negative EV every trade → bleeds.

### Root Cause 2: S2 vel_delta Mismatch (S2 Never Works Correctly)

| Asset | Calibration `min_vel_delta` | Live `min_vel_delta` |
|-------|---------------------------|---------------------|
| BTC   | 0.80c                     | 0.02c               |
| ETH   | 0.70c                     | 0.02c               |
| SOL   | 1.20c                     | 0.02c               |
| XRP   | 0.90c                     | 0.02c               |
| DOGE  | 1.50c                     | 0.02c               |

Live bot fires S2 on noise-level velocity (0.02c). S2 win rate table is **empty** (calibration was run with `SKIP_S2=1`), so it always falls back to `tanh(vel_delta / min_vel)`. At minimum threshold, tanh ratio = 1.0 regardless of threshold value - so WP estimate is identical (0.69) whether vel is strong or noise. S2 enters bad trades confident in a WP estimate computed from a signal 35× weaker than the data behind it.

### Root Cause 3: S1 Dedup Race Condition

In `bot_risk.py:_execute_s1_trade`:

```python
if ticker in bot_state._s1_pending_trades:   # check
    return
# ...
result = await place_order(...)              # YIELDS - another task can enter
if not result["fill_confirmed"]:
    return                                  # exits WITHOUT setting pending_trades
# ...
bot_state._s1_pending_trades[ticker] = {…}  # set (too late)
```

Between the check and the set there is an `await`. A second loop iteration (or LOCKED-phase S1 attempt) can slip through and fire a second order for the same ticker. brain.log shows KXETH-25MAY15-T90000 fired at 14:33:04, 14:34:59, 14:37:36 - identical ratio/dist/rv each time.

### Root Cause 4: Config Has No Real Risk Limits

```json
"max_s1_positions": 20,
"max_s1_positions_per_asset": 5,
"max_consecutive_losses": 999,
"daily_loss_limit_dollars": 99999
```

Up to 25 concurrent S1 positions at $25 each = $625 at risk simultaneously. Zero circuit breakers. Losses compound unchecked.

def test_s1_pending_set_before_fill():
