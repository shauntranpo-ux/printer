# OBI Fix Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the Coinbase WebSocket OBI monitor with Kalshi contract depth OBI computed directly inside `fetch_orderbook()`, keyed by ticker in `bot_state._ticker_obi`, read by `_s2_obi_gate`.

**Architecture:** `_kalshi_obi(yes_arr, no_arr, top_n=5)` is a private pure function added to `bot_market.py` that computes `(no_depth - yes_depth) / (no_depth + yes_depth)` from raw Kalshi orderbook arrays already fetched by `fetch_orderbook()`. The OBI value travels in the `fetch_orderbook()` return dict and is stored to `bot_state._ticker_obi[ticker]` in `bot_loops.py` after each successful fetch. `_s2_obi_gate` is updated to read from that dict, keyed by ticker, eliminating the Coinbase WebSocket background task entirely.

**Tech Stack:** Python 3.11, asyncio, aiohttp, pytest, pytest-asyncio, unittest.mock.

## Background: what exists today

- `obi_monitor.py`: 100-line class `OBIMonitor` that connects to Coinbase Exchange WebSocket, subscribes to `level2_batch` for BTC-USD/ETH-USD/SOL-USD/XRP-USD/DOGE-USD, and stores per-asset OBI in an internal dict.
- `bot.py` line 26: `from obi_monitor import OBIMonitor`
- `bot.py` lines 92-95: instantiates `OBIMonitor` and creates an asyncio task for its `run()` loop.
- `bot_state.py` line 54: `_obi_monitor = None` (set in `main()`)
- `bot_state.py` line 16: `"_obi_monitor"` in `__all__`
- `bot_strategy.py` lines 379-395: `_s2_obi_gate(asset, side, min_obi)` reads `bot_state._obi_monitor.get_obi(asset)`.
- `bot_market.py` `fetch_orderbook()`: already parses `yes_arr = ob.get("yes", [])` and `no_arr = ob.get("no", [])` from the Kalshi orderbook endpoint; return dict has `best_yes_ask`, `best_no_ask`, `best_yes_bid`, `yes_liquidity`, `no_liquidity` - no `"obi"` key yet.

- [ ] **Step 1: Add `_kalshi_obi()` immediately before `async def fetch_orderbook`**

Find the line `async def fetch_orderbook(` in `bot_market.py`. Insert this block two lines above it:

```python
def _kalshi_obi(yes_arr: list, no_arr: list, top_n: int = 5) -> float | None:
    yes_asks = [(p, q) for p, q in yes_arr if q > 0 and p > 0]
    no_asks  = [(p, q) for p, q in no_arr  if q > 0 and p > 0]
    yes_depth = sum(q for _, q in sorted(yes_asks, key=lambda x: x[0])[:top_n])
    no_depth  = sum(q for _, q in sorted(no_asks,  key=lambda x: x[0])[:top_n])
    total = yes_depth + no_depth
    if total < 1e-9:
        return None
    return (no_depth - yes_depth) / total
```

Sign convention: positive OBI = more NO sellers = bullish for YES price. Matches existing `_s2_obi_gate` check (`side == "yes" and obi_val <= min_obi` blocks weak-bullish YES trades).

- [ ] **Step 2: Add `"obi"` to the return dict in `fetch_orderbook()`**

Find the return dict inside `fetch_orderbook()` - it contains `"best_yes_ask"`, `"best_no_ask"`, `"best_yes_bid"`, `"yes_liquidity"`, `"no_liquidity"`. The variables `yes_arr` and `no_arr` are in scope (parsed early in the function from the API response). Add one line:

```python
    return {
        "best_yes_ask": best_yes_ask,
        "best_no_ask":  best_no_ask,
        "best_yes_bid": best_yes_bid,
        "yes_liquidity": yes_liquidity,
        "no_liquidity":  no_liquidity,
        "obi":           _kalshi_obi(yes_arr, no_arr),

```

Note: `yes_arr` and `no_arr` are the raw API arrays from `ob.get("yes", [])` / `ob.get("no", [])`. If the AMM fallback path was triggered (no orderbook depth), these will be empty, causing `_kalshi_obi` to return `None` - which is correct behavior.
